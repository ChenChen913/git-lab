# UI-DESIGN-SPEC — 视觉与交互规范

> 本文是 `../UI 设计.md`（用户与设计方确认的 UI 要求）的工程化落地版本，是 UI/动画实现的硬性依据。验收时按第 7 节逐条检查。

## 1. 定位

**正常、克制、现代、高端、专业的中文开发工具界面**。Apple / Google 系数字产品质感 + 开发者工具专业感 + 适度 Liquid Glass。

明确不做：欧美 AI SaaS 模板、Claude 风、Editorial/杂志风、赛博朋克、霓虹、大面积渐变、玻璃泛滥、到处发光、到处动画、卡片套卡片、过度圆角、过细线条、廉价流程图箭头。

禁止出现无功能意义的英文装饰标签（AI POWERED / SMART WORKFLOW / ENGINE / SYSTEM / CORE / BETA 等）。

## 2. 术语与文案（"界面中文化，专业术语开发者化"）

- Git 核心术语：**英文主标题 + 中文小字辅助**（不是中文主标题+英文括号）：
  - Working Tree / 工作区　Staging Area / 暂存区　Commit History / 提交历史
  - Branch / 分支　HEAD / 当前位置　Merge / 合并　Conflict / 冲突　Remote / 远程仓库
- Git 命令永远原样英文：`git add`、`git switch -c`……
- 普通界面文字（按钮、提示、教程说明）用简洁中文：开始实验、解决冲突、保存改动、返回……
- 右侧面板 Tab：实验、Diff、Stash、Remote、帮助（术语英文，其余中文）。

## 3. Liquid Glass（质感增强，不是视觉主体）

- 允许：半透明背景（白 55–80% 透明度）、backdrop-blur（8–14px）、微妙高光边（白色半透明描边）、柔和双层阴影、轻微背景透光。
- 应用位置：顶栏、状态栏、三个区域卡片、面板容器、Graph 头部、弹窗。**禁止**玻璃叠玻璃、强烈透明、大面积彩色渐变背景。

## 4. 线条与图形质量

- SVG 线条主线 **2.5px** 左右（圆头圆角），拒绝 0.5–1px 的发虚细线；虚影/次要线 1.4px。
- 箭头用 SVG Path（线 + 圆头折角箭头 + 渐变描边 + 流动虚线动画），禁止 CSS border 拼箭头与"──────▶"式机械箭头。
- Commit 节点：实心低饱和色 + 2.5px 白描边 + 柔和投影（feDropShadow）；Merge 节点外加同色半透明外环（双父提示）。
- 分支标签：玻璃白底 + 分支色描边圆角胶囊；HEAD 为深色胶囊 + 琥珀字。

## 5. 色彩（明亮、克制、低饱和）

- 中性面：slate 系浅灰（#f6f8fb 页面底、白/半透明面板）。
- 强调色只用于：当前分支、HEAD、Commit、成功/警告/冲突，其余保持中性。
- 分支调色板取低饱和色系（避免霓虹蓝/赛博绿/高饱和紫）：
  `#5b7fc7 / #5a9e82 / #c2914e / #8d76c9 / #c06f95 / #5596a8 / #7d9a55 / #bd7a55`
- 语义色：成功 emerald-600、警告 amber-500/600、错误 rose-500、提示 sky-600。

## 6. 动画（唯一目的：解释状态变化）

- add：文件芯片从 Working Tree **沿路径平滑移动**至 Staging Area（飞行芯片 + 流动箭头），到达轻微缩放/高亮，容器轻微响应；禁止粒子/爆炸/强发光/大幅旋转。
- commit：暂存区芯片**聚合**成一枚光点飞入 Commit 节点，节点弹入，分支指针 spring 前移。
- branch/switch：标签在节点旁生成 / HEAD 弹跳换位；文件区交叉淡切。
- merge：两条父线汇聚 + 节点强调；ff 指针滑动。
- rebase：旧提交变虚影、逐个重放出新提交（D→D′），必须"看见重放"。
- stash：改动折入 stash 卡片 / pop 弹回。
- push/pull：光点跨过分隔线，远端节点逐个点亮。
- 全部动画克制、有方向性与因果；尊重 prefers-reduced-motion。

## 7. 视觉验收清单（通过/不通过）

1. 线条清晰、粗细合适（主线 2.5px 级别，不细不粗）？
2. Git Graph 有质感（节点投影、玻璃标签、圆润连线）？
3. 箭头自然（SVG Path + 流动感）？
4. 动画流畅且解释状态变化？无无意义动画？
5. 无英文装饰标签？无 Editorial/衬线/AI SaaS 风？
6. 字体清晰克制（系统中文字体 + 等宽仅用于代码）？
7. Liquid Glass 自然、未泛滥？
8. 整体像一个真正的现代软件产品？
9. Commit Graph 是视觉中心，Terminal/文件列表/帮助不与其争夺注意力？

## 8. 字体与布局

- 中文正文：系统无衬线（PingFang SC / Microsoft YaHei / Segoe UI）；代码、命令、文件名、hash：等宽（ui-monospace / Consolas）。不引入任何"设计字体"。
- 布局：现代开发工具式三栏 + 底部终端 + 状态栏；Commit Graph 居中占最大面积；信息层级：一级=当前 Git 状态，二级=Commit/Branch/HEAD/文件状态，三级=命令输出与辅助说明。
- 响应式最低要求：桌面优先，窄窗口水平滚动（min-width），不塌布局。
